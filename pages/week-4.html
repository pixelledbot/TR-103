DAILY TRAINING RECORD

Learning Journal

The fourth week focused on advanced DevOps concepts and the integration of tools studied during the previous weeks. The sessions covered Docker, containerisation, the DevOps lifecycle and the deployment of applications using GitHub, Docker and AWS.

01 DAY ONE

CONTAINERISATION

Introduction to Docker, Images and Containers

The first session introduced Docker as a platform for packaging and running applications in containers. Containerisation helps provide a consistent environment containing the application and its required dependencies.

Docker images were studied as read-only templates used to create containers. Containers are instances of images that provide isolated environments for executing applications.

CONCEPTS COVERED
  • Introduction to Docker
  • Containerisation
  • Docker images
  • Docker containers
  • Image and container relationship
KEY LEARNING

Understood how Docker packages applications and how containers provide isolated execution environments.

Basic Docker Commands

docker --version
docker pull nginx
docker images
docker run nginx
docker ps
docker ps -a
Daily Reflection

This session introduced containerisation as a practical solution for running applications consistently across different environments.

02 DAY TWO

DOCKER PRACTICAL

Dockerfiles and Container Deployment

The second session focused on Dockerfiles and the process of building custom Docker images. A Dockerfile contains instructions that define the environment and steps required to package an application.

Common Dockerfile Instructions

INSTRUCTIONS
  • FROM — selects a base image
  • WORKDIR — sets the working directory
  • COPY — copies project files
  • RUN — executes build-time commands
  • EXPOSE — documents an application port
  • CMD — defines the default start command
PRACTICAL CONCEPTS
  • Creating a Dockerfile
  • Building an image
  • Running a container
  • Mapping application ports
  • Checking container status

Example Dockerfile

FROM python:3.12-slim

WORKDIR /app

COPY . .

RUN pip install --no-cache-dir -r requirements.txt

EXPOSE 5000

CMD ["python", "app.py"]

Building and Running the Image

docker build -t my-web-app .

docker images

docker run -d -p 5000:5000 --name web-app my-web-app

docker ps

Port mapping connects a port on the host machine to a port inside the container, allowing users to access the application through the host.

Daily Reflection

Learned how Dockerfiles simplify application packaging and how images can be used to deploy containers.

03 DAY THREE

DEVOPS LIFECYCLE

Understanding the DevOps Lifecycle

This session focused on the DevOps lifecycle and how different stages work together to support continuous software development and delivery.

DevOps combines development and operations practices to improve communication, automation and the speed of software delivery. It encourages continuous feedback and improvement throughout the application lifecycle.

Main Stages of the DevOps Lifecycle

LIFECYCLE STAGES
  • Plan — define requirements
  • Code — develop application features
  • Build — prepare application packages
  • Test — validate functionality
  • Release — prepare software for delivery
  • Deploy — make the application available
  • Operate — maintain running services
  • Monitor — observe performance and issues
RELATED TOOLS
  • Git and GitHub
  • Jenkins
  • Docker
  • AWS
  • Monitoring tools

The session also explained how these tools connect with one another. GitHub stores source code, Jenkins automates workflow stages, Docker packages applications and AWS provides cloud infrastructure for deployment.

Daily Reflection

Understanding the DevOps lifecycle helped connect the individual tools from earlier sessions into one continuous software delivery process.

04 DAY FOUR

INTERDISCIPLINARY APPLICATION

Deploying a Web Application Using GitHub, Docker and AWS

The fourth session brought together the technologies covered during the training programme. The objective was to understand how a web application can move from source code to a containerised application running on cloud infrastructure.

Deployment Workflow

SOURCE CODE

The application source code is maintained in a GitHub repository. Changes are tracked using Git.

CONTAINERISATION

A Dockerfile defines the application environment and is used to build a Docker image.

CLOUD INFRASTRUCTURE

AWS EC2 provides the virtual server on which the container can run.

APPLICATION ACCESS

Network and security settings allow users to access the deployed application.

Illustrative Deployment Commands

After preparing the application and Dockerfile, the image can be built: 

docker build -t my-web-app .

The image can be tagged for a container registry and uploaded: 

docker tag my-web-app username/my-web-app:latest

docker login

docker push username/my-web-app:latest

On the AWS EC2 server, Docker can be used to retrieve and run the image: 

docker pull username/my-web-app:latest

docker run -d -p 80:5000 username/my-web-app:latest

The example assumes that the application listens on port 5000 inside the container and that the EC2 security group permits the required HTTP traffic. The actual commands depend on the application and server configuration.

Daily Reflection

This session demonstrated how version control, containerisation and cloud infrastructure can work together to deploy a web application.
