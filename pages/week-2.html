DAILY TRAINING RECORD

Learning Journal

The second week focused on cloud platforms, with Amazon Web Services (AWS) as the primary platform. The sessions introduced major cloud providers and covered EC2, S3, IAM, virtual server management, security groups and basic cloud deployment.

01 DAY ONE

CLOUD PROVIDERS

Introduction to Cloud Platforms

The first session introduced major cloud service providers and their role in delivering computing infrastructure over the internet. Cloud platforms provide services that allow users to access servers, storage, databases and networking without purchasing and maintaining all the physical hardware.

An overview of Amazon Web Services (AWS), Microsoft Azure and Google Cloud Platform (GCP) was covered. These platforms offer similar categories of services but differ in their products, pricing structures and management tools.

PLATFORMS STUDIED
  • Amazon Web Services (AWS)
  • Microsoft Azure
  • Google Cloud Platform (GCP)
KEY LEARNING

Understood the purpose of cloud providers and the common categories of services available across different platforms.

Daily Reflection

This session helped connect the cloud computing concepts from Week 1 with the actual platforms used to provide cloud infrastructure.

02 DAY TWO

AWS COMPUTE

Amazon EC2 — Virtual Servers in the Cloud

This session introduced Amazon Elastic Compute Cloud (EC2), a service that provides resizable virtual servers in the AWS cloud. EC2 instances can be used to host websites, run applications and perform computing tasks.

The process of launching an instance was explained, including selecting an Amazon Machine Image (AMI), choosing an instance type, configuring storage and setting network options.

EC2 COMPONENTS
  • Amazon Machine Image (AMI)
  • Instance types
  • Instance state
  • Storage configuration
  • Public and private IP addresses
KEY LEARNING

Learned how EC2 provides virtual computing resources and how instance configuration affects the server's available resources.

Daily Reflection

Understanding EC2 provided practical insight into how virtual servers are created and managed through a cloud provider.

03 DAY THREE

AWS SECURITY AND STORAGE

IAM, S3 and Cloud Resource Management

The third session focused on AWS Identity and Access Management (IAM) and Amazon Simple Storage Service (S3).

IAM is used to manage access to AWS resources through users, groups, roles and policies. It helps ensure that identities receive only the permissions required to perform their tasks.

Amazon S3 is an object storage service used to store and retrieve files such as documents, images, backups and website assets. Data is stored in buckets as objects.

IAM CONCEPTS
  • IAM users
  • IAM groups
  • IAM roles
  • Permission policies
  • Access control
S3 CONCEPTS
  • S3 buckets
  • Objects and keys
  • File uploads
  • Storage and retrieval
  • Bucket permissions

The session highlighted the importance of secure access management and correct storage permissions when working with cloud resources.

Daily Reflection

Learned the difference between identity management and cloud storage, and how both services support secure cloud application development.

04 DAY FOUR

INSTANCE SECURITY

Launching and Managing EC2 Instances

This session explored the practical process of launching and managing an EC2 instance. Special attention was given to key pairs and security groups, which are important for secure access to cloud servers.

Key Pairs

Key pairs are used for secure authentication when connecting to supported EC2 instances. They consist of a public key stored by AWS and a private key retained by the user.

Security Groups

Security groups act as virtual firewalls for EC2 instances. They control inbound and outbound traffic through configured rules.

IMPORTANT CONCEPTS
  • Instance launching
  • Key pair selection
  • Inbound rules
  • Outbound rules
  • SSH access
COMMON PORTS
  • SSH — 22
  • HTTP — 80
  • HTTPS — 443

Access rules should be restricted to the required sources and ports rather than exposing services unnecessarily.

Daily Reflection

This session demonstrated that launching a cloud server involves both resource configuration and careful security management.

05 DAY FIVE

CLOUD DEPLOYMENT PRACTICAL

Hosting a Website and Uploading Files to S3

The final session focused on applying the AWS concepts through basic cloud deployment tasks. The process of hosting a simple website using an EC2 virtual server was explored.

A web server can be installed on an EC2 instance to serve website files over HTTP. The instance's security group must allow the required web traffic.

Example EC2 Web Server Setup

After connecting to a suitable Ubuntu EC2 instance, a web server such as Nginx can be installed: 

sudo apt update
sudo apt install nginx -y
sudo systemctl start nginx
sudo systemctl enable nginx
sudo systemctl status nginx

Once the HTTP security group rule is configured, the website can be accessed using the instance's public IP address.

Uploading Files to Amazon S3

The session also covered creating an S3 bucket and uploading files through the AWS Management Console.

  1. Open the Amazon S3 service.
  2. Create a uniquely named bucket.
  3. Review the bucket access settings.
  4. Open the bucket and choose Upload.
  5. Select the required files.
  6. Complete the upload and verify the objects.
Daily Reflection

Hosting a website and uploading files to S3 connected cloud concepts with practical use cases involving compute and storage services.
